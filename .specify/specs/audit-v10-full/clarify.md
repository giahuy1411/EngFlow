# Clarification ledger — audit-v10-full

Decisions taken before implementation, each with the reason and the evidence that forced it.

| # | Question | Decision | Reason / evidence |
|---|---|---|---|
| C1 | The working tree is RED (425/432 backend tests) because of an in-flight streak refactor. Park it, revert it, or finish it? | **Finish it and make it run for real.** | Owner decision. The refactor is ~80% complete, the schema SQL is authored and reviewed, and the whole point of the feature (a login is not a study day) is unproven until it runs. Parking it would leave the tree red and the feature untested. |
| C2 | The refactor's README says "Deployment gate — NOT deployed" and `deploy.sql` says "authored, not executed". Deploy anyway? | **Yes — execute `deploy.sql` with cutover `2026-09-20`.** | The new code throws when the policy row is missing (`StudyActivityService.effectiveFrom()`), so code and schema are one unit. Leaving the schema out leaves the suite red forever. This is a development database in a graduation project, not production. |
| C3 | Cutover date | **2026-09-20** | Owner decision. Gives room to back up, verify and rebuild before the first day of real study-day semantics. |
| C4 | The design prompt contains factual errors about this codebase ("Lucide React", Tailwind utility names, a `scale(1.1)` pricing card that does not exist). Force the code to the prompt, or correct the prompt? | **Force the concrete visual claims; correct the false ones.** | Owner asked for the literal prompt. Where the prompt makes a *visual* claim (container width, yellow hero circle, dashed connector, scaled featured card, rotated badge, squiggle divider, marquee, arrow affordance) it is implemented. Where the prompt is simply wrong about the stack (React icons) or prescribes utility class names the codebase never used, the prompt is rewritten rather than adding dead classes. |
| C5 | Backlog: 4,848 empty `correct_answer`, 9 LISTENING without `audio_url`, 8 legacy `zz*` users, 4 `exercises_bak_v5*` tables, 3 legacy error shapes | **All four, but measure first.** | Owner decision, explicitly "research and verify carefully before doing". Order is fixed: re-measure → investigate any drift → backup → act on an explicit ID list → verify → re-assert parity. |
| C6 | Empty `correct_answer` rows | **Classify, do not synthesize keys.** | The grader already returns `ungradeable=true` and the UI labels them. audit-v8 measured that `mode=full` with `qwen2.5:1.5b` produces junk keys (`"1. a"` for a grammar gap). Inventing keys would corrupt the gradebook. |
| C7 | LISTENING audio backfill | **Only if the real TTS→Cloudinary path is proven in this environment.** | `issues.md` sets this condition. AGENTS.md records that fake bytes produce 400/500 and previously caused a wrong "demo credentials" conclusion; a real media file is required to test the path. If it cannot be proven, record a per-row reason instead. |
| C8 | Legacy Redis `user:login_days:*` keys | **Measure the key count and TTL first, then decide between reading them as legacy history and copying them to durable storage.** | `StudyActivityService.snapshot()` already reads them as `legacyAccessDays` with a 90-day TTL. Copying is only justified if the measured expiry is imminent. |
| C9 | Schema changes | **Direct SQL only, no Flyway migration.** | Constitution P3: `ddl-auto=update`, Flyway disabled. |
| C10 | Performance work | **Only with before/after numbers.** | Constitution P5. The new `/api/streak/snapshot` path has never been measured and is the primary new candidate. |
| C11 | Index drops / new Redis caches | **Not without a representative workload showing a win.** | `performance.md` from v9 reached the same conclusion with measurements; re-affirmed here. |
| C12 | Second pass | **Mandatory and wider.** | Owner requirement. Adds adversarial cases for the new endpoint, streak boundary conditions, a repeated browser sweep, and a cross-artifact consistency check. |
| C13 | Test counts | **Read from the run log, never from `target/surefire-reports` XML.** | AGENTS.md records stale XML from a deleted test class inflating the aggregate by 8. |
| C14 | Destructive DB steps | **Fresh backup + explicit ID list + `SET QUOTED_IDENTIFIER ON` + `Msg \d+` scan.** | AGENTS.md: a bare `email LIKE 'zz%'` deleted four baseline users in v9 (F111), and `sqlcmd` still exits 0 when a batch fails. |
